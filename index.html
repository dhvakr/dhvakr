Work

Five years of numbers that moved in the right direction.

Where there is a bar below, it is something I measured before and after: the tick is where the number started, the bar is where it ended.

Strategy (formerly MicroStrategy)

Software Engineer, IC3  ·  March 2026 — present

I build and operate a Kubernetes-based multi-tenant cloud platform that provisions customer analytics environments across GCP, AWS, Azure, StackIT, IBM Cloud and self-hosted — a Spring Boot control plane driving Temporal workflows, Helm and Terraform.

Six target platforms with six different ideas of what a network, a disk and an identity are, reconciled behind one control plane. Every environment has to come up isolated from its neighbours, reproducible from the spec, and recoverable when a provision dies halfway through.

Solinas Integrity

Software Engineer II  ·  Sept 2024 — Mar 2026 Employee Of The Year

Owned the technical roadmap for an AI SaaS platform serving 70+ enterprise clients, and led a five-person team through delivery. Designed four Java services from scratch and held them to resilience standards so the platform stays available when inference traffic spikes. Alongside that: HLD and LLD for new surfaces, 50+ code reviews, and a test-coverage floor of 90%.

  • REST API P95 latency — indexing and Redis caching 2s→<1s
  • Dashboard analytics query — Kafka pipeline into Redshift 8s→<2s
  • Notification throughput — service rewritten Java → Go +40%
  • AWS cost on that same path −30%
  • Manual deployment time — automated CI/CD 3h+→<15m

Grootan Technologies

Software Engineer I  ·  Feb 2022 — Aug 2024 Best Find Of The Year

Built and operated the backend of a Keycloak-based identity SaaS used by 4M+ users across banking and public-sector clients. Shipped custom authentication flows — QR login, passkeys, magic links — through Spring Boot and the Keycloak SPI, and kept them compliant under audit. Also built the internal and external APIs other teams consumed, and the React dashboards that read them.

  • Audit log query latency — Kafka outbox into MongoDB 3s→<800ms
  • Sustained login throughput in production 3k/s→5k+/s
  • Customer onboarding — custom IAM authenticator flow −90%
  • Authentication route latency — the hot path itself 1.8s→420ms
  • Debugging time — OpenTelemetry, Sentry, Jaeger −40%

Ownership

The half of the job that isn’t writing code.

Owning what gets built and why, what it costs to run, and whether the people around it get better. This is the part that doesn’t fit in a commit history.

  1. 01
    Set the security bar after a penetration test A test flagged SSRF and anonymous access on web services. I assessed WAF coverage across both AWS and Azure and defined the remediation, rather than filing the findings and waiting for someone else to scope it.
  2. 02
    Owned the roadmap, not just the tickets Set the technical direction for an AI SaaS platform serving 70+ enterprise clients, and aligned sprints with product so delivery was predictable rather than heroic.
  3. 03
    Took $120K a year off the cloud bill — then argued for where it went Consolidated microservices and removed redundant auth calls. The harder part was making the case to reinvest the saving into security work across teams, instead of letting it quietly become margin.
  4. 04
    Turned demos into a feedback loop 15+ product demonstrations and field enablement lifted customer acquisition by 20%. The objections I heard in those rooms came back as roadmap items.
  5. 05
    Built the bench Led a five-person team, directed HLD and LLD for new surfaces, mentored through 50+ code reviews, and held a 90% test-coverage floor in CI so quality was a gate rather than an opinion.
  6. 06
    Went looking for the next problem Noticed that teams can get an AI agent working in an afternoon and then stall for months because nobody will let it near production. That gap is what I am building Ikat for.

kubectl-reach

building

The question every operator asks and no dashboard answers: what can this pod actually reach, right now? It composes NetworkPolicies, RBAC bindings and service-mesh identity into a single reachability answer — and names the exact rule doing the allowing, so you can go and change it.

GoKubernetesNetworkPolicyRBACkubectl plugin

A question I have answered by hand across six platforms. That is usually the sign it should be a tool.

envctl

building

A control plane that provisions and reconciles whole customer environments across AWS and Azure from one declarative spec. Built on durable workflows, so a provision that dies halfway resumes rather than stranding a tenant in a half-built state someone has to unpick by hand.

GoTemporalTerraformHelmMulti-cloud

Drift detection and rollback as first-class operations, not a runbook.

planguard

building

Catches a query-plan regression before it reaches production: snapshot the plan for every query in CI, then fail the build when one quietly turns into a full-table scan.

JavaPostgreSQLCIStatic analysis

Written because I found one carrying 79% of production RDS load, and nothing in the pipeline would have caught it.

Building now

And one thing that is not a side project.

ikat

The control plane between AI agents and real systems.

Agents can already reach your database, your cloud account and your customers' data. What nobody can answer is what they touched, on whose behalf, and what it cost. Ikat puts scoped identity, policy and a complete record in the path — so security has a way to say yes.
